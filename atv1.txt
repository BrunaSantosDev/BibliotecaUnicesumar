1. Activity é uma classe desenvolvida para auxiliar na interação de um app com o usuário, sendo essencialmente uma tela. Cada aplicativo Android tem uma activity principal, que é a primeira tela exibida, e cada activity (tela) tem um ciclo de vida com início e fim gerenciado pelo sistema. O ciclo de vida de uma activity funciona da seguinte forma:
- onCreate(): Este método é invocado ao abrir o app e também quando uma outra activity é iniciada. É o momento para realizar as inicializações e verificações essenciais da tela, como a definição do layout ou verificar se o usuário está conectado à internet.
- onStart(): Após a execução do onCreate(), este método é chamado, e ele é quem cria toda a parte visível da tela para o usuário, porém ela ainda não está interativa.
- onResume(): Quando a activity está em primeiro plano e pronta para a interação, este método é chamado. Ele também é invocado quando o app retorna do estado de pausa para em foco novamente, assim tornando o app e a tela interativos.
- onPause(): Este método é chamado quando a aplicação sai do foco e fica pausada em background, por exemplo, quando outra activity dentro do app é iniciada ou quando o usuário vai para a tela inicial do dispositivo. Desta forma, a activity ainda pode estar visível, mas não é interativa para o usuário.
- onDestroy(): Este é o último método do ciclo de vida de uma activity. Ele finaliza a execução da tela/activity e é chamado antes que a activity seja completamente destruída pelo sistema. A destruição pode ocorrer para liberar recursos do dispositivo ou iniciar o processo em outra página/activity dentro do app.

2. Esses três elementos trabalham juntos para executar tarefas específicas, como por exemplo adicionar e exibir uma lista de tarefas. O EditText nada mais é que uma caixa de inserção de texto, onde o usuário digita a atividade que deseja adicionar à lista de tarefas. O Button é o botão que executa uma ação quando pressionado, nesse caso, adicionando o texto digitado no EditText à lista de tarefas. Quando o usuário clica no botão, o código do aplicativo acessa o EditText, obtém o que foi digitado e processa essa informação. Já o ListView é o responsável por exibir todos os itens adicionados à lista, mas ele não recebe os dados diretamente do EditText ou do Button. Em vez disso, ele é alimentado por um terceiro componente chamado Adapter, que gerencia os dados da lista. Quando o Button é clicado e a tarefa escrita pelo usuário é extraída do EditText, essa tarefa é adicionada à lista de dados que o Adapter do ListView manipula. Após essa adição, o Adapter notifica o ListView para se atualizar, fazendo com que o novo item apareça na lista, e consequentemente na tela para o usuário.

3. O Adapter é um componente fundamental para o funcionamento do ListView, pois ele atua como uma ponte entre os dados e a exibição na interface do usuário, usando como exemplo o caso descrito na questão, ele seria o responsável por converter os itens da lista de dados em elementos visuais que o ListView exibirá. Sempre que um novo item é adicionado, removido ou alterado na lista de tarefas, o adapter notifica o ListView para que ele atualize sua exibição automaticamente, garantindo que os usuários vejam sempre a versão mais recente da lista. Sem o Adapter, o ListView não conseguiria interpretar e organizar os dados de maneira eficiente.
